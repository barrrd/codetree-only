# [삼성 기출] 아기 바다거북의 대모험: 해저 화산 지대

> **문제 링크**: [코드트리 - 아기 바다거북의 대모험: 해저 화산 지대](https://www.codetree.ai/ko/frequent-problems/samsung-sw/problems/a-little-sea-turtles-big-adventure/description)

---

## ⚠️ 구현 시 주의해야 할 핵심 포인트

### 1) 바다거북은 ID마다 현재 상태를 기준으로 BFS를 다시 수행
바다거북은 ID가 작은 순서대로 이동하며, **앞선 거북이의 이동 결과가 즉시 다음 거북이의 경로 탐색에 반영**됩니다.

따라서 한 턴의 시작 상태에서 모든 거북이의 경로를 미리 계산하면 안 되고, 각 거북이가 이동할 때마다 현재 `tarr`를 기준으로 BFS를 새로 수행해야 합니다.

* **오류 예시:** 턴 시작 시 모든 거북이의 최단 경로를 한 번에 계산하면, 앞 거북이가 비운 칸이나 새롭게 차지한 칸이 뒤 거북이의 탐색에 반영되지 않습니다.
* **핵심:** `1번 BFS → 1칸 이동 및 지도 갱신 → 2번 BFS → ...` 순서로 처리해야 합니다.
* **➡️ 해결 방법:**
    * 살아있는 거북이만 관리하는 `turtle` 딕셔너리를 사용합니다.
    * `sorted(turtle.keys())` 순서로 각 거북이에 대해 BFS를 수행합니다.
    * 한 거북이가 이동하면 즉시 `tarr`와 `turtle`의 위치를 갱신합니다.
    * 안식처에 도착한 거북이는 즉시 `tarr`와 `turtle`에서 제거합니다.

---

### 2) 최단 경로 전체를 저장하지 말고 `parent`로 첫 이동 칸만 복원
거북이는 안식처까지 실제로 한 번에 이동하는 것이 아니라, **최단 경로의 첫 번째 칸으로 단 한 칸만 이동**합니다.

따라서 전체 경로 리스트를 따로 저장할 필요 없이 BFS 과정에서 각 칸의 이전 위치인 `parent`만 저장하면 됩니다.

* **오류 예시:** 시작점 기준 `dist == 1`인 칸을 선택하면, 현재 위치에 인접한 모든 이동 가능 칸이 거리 1이므로 어떤 칸이 안식처까지의 최단 경로에 포함되는지 알 수 없습니다.
* **핵심:** 목적지를 찾은 후 `parent`를 안식처에서 시작점 방향으로 역추적하여 시작점 바로 다음 칸을 찾습니다.
* **➡️ 해결 방법:**
    * BFS에서 처음 `(nr, nc)`를 방문할 때 `parent[nr][nc] = (cr, cc)`로 저장합니다.
    * 탐색 방향을 **우 → 하 → 좌 → 상** 순서로 유지하여 최단 경로 동률 시 첫 이동 우선순위를 반영합니다.
    * 안식처에서 `parent`를 따라 올라오다가 `parent[tr][tc] == (sr, sc)`가 되는 칸을 찾습니다.
    * 해당 `(tr, tc)`가 이번 턴에 실제로 이동할 한 칸입니다.
    * 안식처까지 경로가 없다면 기존 `(sr, sc)`를 그대로 유지합니다.

### 3) 지도 상태를 역할별로 분리하여 관리

이 문제는 산호초, 화석, 살아있는 거북이, 화산, 누적 열기 등 여러 상태를 동시에 관리해야 하므로 하나의 배열에 모든 정보를 몰아넣으면 조건문이 복잡해집니다.

현재 구현에서는 다음과 같이 역할별 자료구조를 분리했습니다.

```text
arr
  0 : 이동 가능한 칸
  1 : 산호초
  2 : 화석

tarr
  0 : 살아있는 거북이 없음
  id: 해당 위치에 존재하는 살아있는 거북이 ID

tutle[id]
  (r, c)
  : 살아있는 거북이의 현재 위치
  : 안식처에 도착하거나 화석화되면 딕셔너리에서 삭제

var[id]
  [r, c, pressure, max_p]
  : 화산 위치 (r, c)
  : 현재 마그마 압력 pressure
  : 분출 임계치 max_p

volcano_pos[r][c]
  0 : 화산 없음
  id: 해당 위치에 존재하는 화산 ID
  : 열기가 전파된 칸에 화산이 있는지 O(1)로 확인하기 위해 사용

varr[r][c]
  : 현재 턴 동안 해당 칸에 누적된 총 열기
  : 여러 화산의 열기가 도달하면 += 방식으로 누적
  : 모든 연쇄 분출과 화석화 판정이 끝난 후 0으로 초기화

answer[id]
  : 해당 거북이의 최종 결과
  : 안식처 도착 시 도착한 turn 저장
  : 화석화 시 -1 저장

count
  : 안식처에 도착하거나 화석화되어 더 이상 이동하지 않는 거북이 수
  : count == M이면 시뮬레이션 종료
```

특히 거북이의 BFS에서는 다음 두 조건을 이용하여 이동 가능 여부를 판단합니다.

```text
arr[nr][nc] != 0
→ 산호초(1) 또는 화석(2)이므로 이동 불가

tarr[nr][nc] != 0
→ 다른 살아있는 거북이가 있으므로 이동 불가
```

반면 화산은 거북이가 진입할 수 있으므로 `arr`의 장애물로 표시하지 않고, `var`와 `volcano_pos`를 통해 별도로 관리합니다.

또한 `varr`는 화산의 위치를 저장하는 배열이 아니라 **현재 턴의 누적 열기 배열**로만 사용하여 역할이 섞이지 않도록 했습니다.
